# 架构说明 & 怎么继续往上加功能

## 1. 分层与依赖方向

```
features/  （页面 + MobX controller + 路由）
    ↓ 只允许往下
repositories/  （只碰 models + Hive 箱子）
    ↓
services/ + core/  （CAS、门户访问、主题、网络、存储）
    ↓
models/ + utils/  （纯数据、纯函数）
```

`ui/` 是横切层：任何 feature 都能用，它自己不依赖 features。

约束是靠"文件放对位置"保证的，不是靠框架。加功能时最容易破坏的一条是：**别在页面里直接 new Dio 或直接读 Hive**。

## 2. 两个刻意的偏离（以及怎么改回去）

Kazumi 那套骨架用了代码生成：MobX 的 `@observable` + `mobx_codegen`，Hive 的 `@HiveType` + `hive_ce_generator`。本项目**没有用 codegen**，原因很实在：`flutter run` 之前必须先跑 `build_runner`，一步忘掉就是一片 `_$XxxController 未定义`。为了"clone 下来就能跑"，改成：

| 地方 | Kazumi 写法 | 本项目写法 |
|---|---|---|
| 状态 | `class X = _X with _$X; @observable int a;` | `final a = Observable(0);` + `runInAction(() => a.value = 1)` |
| 持久化 | `@HiveType` + `TypeAdapter` | `Box<String>` 存 `jsonEncode(entity.toJson())` |

**想换回去**：给 controller 加 `part 'x_controller.g.dart'`、把字段改成 `@observable` 并补 `@action`；给 model 加 `@HiveType`/`@HiveField` 并注册 adapter。然后：

```bash
flutter pub add --dev build_runner mobx_codegen hive_ce_generator
dart run build_runner build --delete-conflicting-outputs
```

改之前先确认 `flutter_mobx` 与你装的 `mobx_codegen` 大版本一致，否则生成代码的 mixin 名会对不上。

## 3. 依赖注入的真实形态

`core/graph.dart` 里的 `AppGraph` 是组合根：所有服务、仓储、controller 在一处 `new` 出来，用 `late final` 做懒单例。页面通过 `AppGraph.instance.xxx` 拿。

为什么不走容器自动注入：`flutter_modular` 7.x 的 `addSingleton<T>(T.new)` 是按构造函数位置参数自动解析的，服务依赖一多就变成"注册顺序玄学"。显式装配多写十行，但改版本、换实现时不会整片编译不过。**路由**仍然交给 flutter_modular（`createModule` + `context.pushNamed`）。

## 4. 加一个页面（标准动作）

1. `features/<新功能>/<新功能>_page.dart` —— `Scaffold` 起点
2. `features/<新功能>/<新功能>_controller.dart` —— MobX Store（可选，页面无状态就不建）
3. `features/<新功能>/<新功能>_route.dart`：

```dart
final xxxModule = createModule(
  path: '/xxx',
  register: (c) {
    c.route('/', child: (ctx, state) => const XxxPage());
  },
);
```

4. 在 `app_module.dart` 里 `..module(xxxModule)`
5. 跳转用 `context.pushNamed('/xxx')`，返回用 `context.pop()`

跨页传参不走 URL：写进 `AppGraph.instance.navArgs`（见 `graph.dart` 的 `NavArgs`），省掉参数解析的类型体操。

## 5. 验收清单（每次交付前跑一遍）

```bash
flutter analyze     # 必须 No issues found
flutter test        # 必须全绿
```

再看人工项：

- [ ] 冷启动不白屏（有骨架或空态）
- [ ] 断网时首页给可读错误 + 重试
- [ ] 杀进程重开：课表、专注记录、登录态都还在
- [ ] 深色 / 纯黑 / 跟随系统三种模式没有"黑字黑底"
- [ ] 窄屏（<600dp）与平板（≥600dp，走 NavigationRail）都点得通
- [ ] 所有异步失败都有 SnackBar 或错误态，不静默

## 6. 已知的坑（都踩过了）

| 现象 | 原因 | 处理 |
|---|---|---|
| `flutter test` 报 `Invalid WebSocket upgrade request` | 机器上设了 `HTTP_PROXY`，flutter_tester 的本地连接被代理 | 跑测试前 `unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy` |
| 每个文件都提示 `package:flutter/material.dart` 已废弃 | Flutter 3.50 起 material 迁到 `material_ui` 包 | `analysis_options.yaml` 里 `errors: deprecated_member_use: ignore`（整库级迁移后续再做） |
| `dynamic_color` 的 `ColorScheme` 和 Flutter 的不是同一个类 | 3.50 之后两者来自不同包 | 只从动态配色里取 `primary` 当种子色，不做类型传递（`app.dart`） |
| AES 初始化报 `No algorithm registered of type Padding` | `encrypt` 包 padding 名大小写敏感 | 写 `'PKCS7'` |
| 登录成功但访问门户仍 302 | 自动重定向丢了中间跳的 `Set-Cookie` | `followRedirects: false` + 手动逐跳跟随 |
