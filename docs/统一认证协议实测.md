# 统一认证（金智 authserver）协议实测记录

> 目标：`https://portal.caii.edu.cn` 的表单登录 → 拿到可用于门户的会话 Cookie。
> 取证方式：直接对线上服务器发请求（curl / Node / Dart 三条独立路径交叉验证），2026-11-13。

---

## 1. 站点结构

| 项 | 值 |
|---|---|
| 门户域名 | `https://portal.caii.edu.cn` |
| 门户入口 | `/ywtb-portal/standard/index.html?browser=no` |
| 认证服务 | `https://authservernew.caii.edu.cn/authserver` |
| 产品 | 金智教育 统一身份认证（authserver，主题 `caiiThemeNew`，版本戳 `20260703.154014`） |
| 全站保护 | 门户任意路径未登录时 `302 → authserver/login?service=<原路径>` |

实测（curl，无 Cookie）：

```
GET /ywtb-portal/standard/index.html?browser=no    → 302 → authservernew.../login?service=…
GET /ywtb-portal/openplatform/api/getUserInfo      → 302 → authservernew.../login?service=…getUserInfo
GET /                                              → 301 → /ywtb-portal/index.html
```

结论：**门户整体挂在 CAS 过滤器后面**。只要拿到能过 CAS 的会话，直接带 Cookie 请求任意门户路径都是 200，不需要额外的 token 交换。

## 2. 登录页字段（实测抓取）

`GET /authserver/login?service=…` 返回 200，`Set-Cookie: route=…; JSESSIONID=…`，表单里：

```html
<form class="loginFromClass" method="post" id="pwdFromId" action="/authserver/login">
  <input id="username"  name="username"     type="text"     placeholder="请输入学号/工号">

  <input id="saltPassword" name="password"  type="hidden">     <!-- 提交的是这个 -->

  <input type="hidden" id="_eventId"  name="_eventId"  value="submit">

  <input type="hidden" id="dllt"      name="dllt"      value="generalLogin">
```

## 3. 密码加密（页面 `static/common/encrypt.js`，原文节选）

```js
function getAesString(n, f, c) {
  f = CryptoJS.enc.Utf8.parse(f);          // key  = salt
  c = CryptoJS.enc.Utf8.parse(c);          // iv   = 16 位随机串
  return CryptoJS.AES.encrypt(n, f, {iv: c, mode: CryptoJS.mode.CBC, padding: CryptoJS.pad.Pkcs7}).toString();
}
function encryptAES(n, f) { return f ? getAesString(randomString(64) + n, f, randomString(16)) : n; }
function encryptPassword(n, f) { return encryptAES(n, f); }
var $aes_chars = "ABCDEFGHJKMNPQRSTWXYZabcdefhijkmnprstwxyz2345678";
```

因此等价实现（本项目 `services/cas/cas_crypto.dart`）：

```
key   = salt（16 字符）
iv    = 从 $aes_chars 里随机取 16 个字符
plain = 从 $aes_chars 里随机取 64 个字符 + 密码
out   = base64( AES-128-CBC-PKCS7(plain, key, iv) )
```

注意两点，踩过才知道：

1. `encrypt.js` 里的 `saltPassword` 才是提交字段，明文框 `passwordText` 提交时会被 `disabled`。
2. Dart 侧 `encrypt` 包的 padding 名必须写 **大写** `'PKCS7'`，写小写会被 pointycastle 报 `No algorithm registered of type Padding`。

## 4. 提交与响应（实测）

```http
POST /authserver/login?service=<urlencode(门户首页)>
Content-Type: application/x-www-form-urlencoded
Cookie: route=…; JSESSIONID=…

username=<学号>&password=<AES 密文>&captcha=&_eventId=submit&cllt=userNameLogin
&dllt=generalLogin&lt=&execution=e1s1&rmShown=1
```

三种结果：

| 情况 | 状态码 | 特征 |
|---|---|---|
| 成功 | 302 | `Location: <service>?ticket=ST-xxx-…`，同时下发 `CASTGC` |
| 账号/密码错 | 401 | 页面 `<span id="showErrorTip">该账号非常用账号或用户名密码有误</span>`，`execution` 递增为 `e1s2` |
| 需要验证码 | 200 | 页面 `var needCaptcha = "true"`，`/authserver/getCaptcha.htl` 出 `image/jpeg` |

实测一次（错误密码，Dart 实现，与 Node 实现结果一致）：

```
GET   status=200 salt=YWeCpOthbJxnFt1o execution=e1s1 cookies=route,JSESSIONID
POST  status=401
errorTip=该账号非常用账号或用户名密码有误
needCaptcha=false
```

→ 说明**加密格式被服务端接受了**：格式错会是参数/解密类错误，不会是这条账号提示。

## 5. 拿会话的四步（本项目实现）

1. `GET login?service=…` → 解析 `pwdEncryptSalt` / `execution` / `lt`，保存 `JSESSIONID`。
2. 算密码密文（见 §3）。
3. `POST` 表单（见 §4）。
4. 302 后**逐跳手动跟随** `Location`（`followRedirects: false`），每一跳的 `Set-Cookie` 都写进 cookie jar，直到 200。

关键点：dio 默认自动重定向时，中间跳的 `Set-Cookie` 不会进 jar，`CASTGC` 就丢了 —— 这是绝大多数"登录成功但访问门户还是 302"的原因。

`CASTGC` 的用途：会话过期后，带着它 `GET service?service=…`（不带 ticket）CAS 会静默返一张新票，这就是 `CasAuthService.renew()`，也是"无感续期"的全部秘密。

退出：`GET /authserver/logout` 后清空 jar。
