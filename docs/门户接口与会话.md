# 门户接口与会话（真机实测）

> 记录 2026-11-14 用 ADB 在真机（PLID110 / Android 17）上跑通的东西，以及踩到的坑。

## 1. 登录态到底是哪几个 Cookie

网页登录（WebView 里）成功后，本机会拿到这些 Cookie（实测导出）：

| Cookie | 域 | 作用 |
|---|---|---|
| `MOD_AUTH_CAS` | portal.caii.edu.cn | **门户会话的真相**，值是 `MOD_AUTH_ST-...` |
| `JSESSIONID` / `asessionid` | portal.caii.edu.cn | 门户后端会话 |
| `route` | portal.caii.edu.cn | 网关路由 |
| `org.springframework...LOCALE` / `MULTIFACTOR_BROWSER_FINGERPRINT` / `happyVoyage` | authservernew.caii.edu.cn | CAS 侧会话与指纹 |

**没有 `CASTGC` 也能用**：门户只认 `MOD_AUTH_CAS`。所以"网页登录后同步会话"这条路是可行的，
不需要非得在 App 里走一次账号密码。

## 2. 关键 bug：domain 里有协议，导致 Cookie 全被丢弃

`webview_flutter` 在 Android 上返回的 `WebViewCookie.domain` 是 **带协议的整串**
（`https://portal.caii.edu.cn`）。我们一开始拿它做域名匹配：

```dart
host == domain || host.endsWith('.$domain')   // "portal.caii.edu.cn" vs "https://portal.caii.edu.cn" → false
```

结果：Cookie 全部抓进本机，但拼 `Cookie` 请求头时一条都匹配不上，dio 拿着空头去敲门 →
门户 302 → App 判"未登录"。症状就是"网页明明登录了，App 说没登录"。

修法：`RawCookie.normalizeDomain()` 统一收敛成纯主机名（去协议、去端口、去前导点）。
修完当场验证：诊断页 `[200] portal.caii.edu.cn/...` → 可用。

## 3. 门户（金智 AMP）的公开 JSONP 接口

`https://portal.caii.edu.cn/jsonp/constant.json` 是接口字典，实测可用的：

| 接口 | 返回 |
|---|---|
| `/jsonp/userInfo.json?amp_jsonp_callback=cb` | `userName`(姓名) / `userId`(学号) / `userDepartment`(院系) / `userPhoto`(头像，可能 null) / `hasLogin` |
| `/jsonp/myAppService.json?amp_jsonp_callback=cb` | 我的应用列表（含 appId / appName / deployPrefix），「我的课表」= `4770397878132218`，`deployPrefix=https://portal.caii.edu.cn/jwapp` |
| `/jsonp/appBizInfo.json?appId=...` | 单个应用详情（含版本、authUrl） |
| `/jsonp/checkLogin` | `true` / `false` |

App 里已经用 `userInfo.json` 把「更多」页的占位名换成真实姓名 + 院系。

## 4. 课表：为什么不能直接写接口

- `https://jw.caii.edu.cn` 是金智 **选课** 应用（`/xsxkapp`），`/jwglxt/...` 一路 404；
- 课表在 **门户** 的 `/jwapp/sys/wdkb/`（金智「我的课表」）；
- 直接请求 `/jwapp/sys/wdkb/*default/index.do` → **403**，必须带门户生成的一次性 `gid_` 令牌
  （用户从门户点进去时那个长串）。令牌是一次性的，写死必然过期。

所以实现换成**在网页里截 XHR**（`features/kbimport/kb_capture_page.dart`）：
用户正常点进「我的课表」，我们给 `XMLHttpRequest`/`fetch` 打补丁，把页面自己拉到的
课表 JSON 截下来 → `JwxtParser` 解析 → 写入本地课表。学校改版、换路径都不受影响。

## 5. 扫码签到

签到页是"登录后能打开的网页"，不需要知道它具体是哪个应用：

`扫一扫 → 命中校内域名 → 带着会话的 WebView 打开`。
会话同步是全局的（`RawCookieStore` 按域名匹配），所以 `*.caii.edu.cn` / `*.cctua.edu.cn`
下任何页面都能直接进。

## 6. 个人信息页（头像）

地址：`https://authservernew.caii.edu.cn/personalInfo/personalMobile/index.html#/home`。
实测在 App 的 WebView 里**可以直接进**（带着已有的 CAS Cookie），不需要再登一次。

页面结构（真机 DOM）：

```html
<div class="personal_img"><img src="data:image/png;base64,..." width="80" height="80"></div>
```

两个要点：

1. 头像是 **base64 内联**，不是链接 —— `Image.network` 渲染不出来，要用 `Image.memory`；
   `AvatarSource.isDataUri/decodeDataUri` 负责这件事（`ui/avatar_view.dart`）。
2. 原始 base64 有 **738KB**（约 550KB 二进制），直接存会让会话 JSON 臃肿；
   `AvatarSource.shrinkDataUri()` 用 `instantiateImageCodec` 缩到 160px 再存，一般 30–60KB。

抓取逻辑就一句 `document.querySelector('.personal_img img')`，姓名取
`[class*=personal_name]` 里的第一段中文（带"个人中心/账号"这类页面标题的黑名单）。
万一改版抓不到，会把那块 DOM 打进「诊断 → 最近日志」，照着真实类名改即可。
